A small request for the weather station's Grafana proxy

From aycweather.com, the Austin Yacht Club weather page

Help Part Two

Status after the first try: the headers are arriving (thank you!), but a browser still rejects them for two reasons. Fix both and it works. Part One, the original ask, is further down.

1. The origin value needs its scheme

The rule currently sends access-control-allow-origin: aycweather.com. Browsers compare it against the page's origin character for character, so it has to be exactly: 

https://aycweather.com

2. The OPTIONS preflight has to return a 2xx

The preflight still comes back HTTP/2 404. Grafana doesn't answer OPTIONS, and a Cloudflare response-header rule can only add headers, it can't change the status code, so the browser throws the response away. Something has to answer OPTIONS with a 204. On Cloudflare the cleanest way is a tiny Worker on just this path.

The Worker (copy and paste)

export default {
  async fetch(request) {
    const cors = {
      "Access-Control-Allow-Origin": "https://aycweather.com",
      "Access-Control-Allow-Methods": "POST, OPTIONS",
      "Access-Control-Allow-Headers": "Content-Type",
      "Access-Control-Max-Age": "86400",
    };
    if (request.method === "OPTIONS") {
      return new Response(null, { status: 204, headers: cors });
    }
    const res = await fetch(request);
    const out = new Response(res.body, res);
    for (const [k, v] of Object.entries(cors)) out.headers.set(k, v);
    return out;
  },
};

Where it goes

  • Cloudflare dashboard → Workers & Pages → Create → start from "Hello World" → replace the code with the block above → Deploy.
  • Then in the ageddon.com zone → Workers Routes → Add route: route grafana.ageddon.com/api/ds/query, pointing at that Worker.
  • With the Worker in place, the response-header rule can be deleted. The Worker sets the same headers with the corrected origin, and nothing else on the server changes.

Check

When this prints HTTP/2 204 and access-control-allow-origin: https://aycweather.com, it's done:

curl -s -D - -o /dev/null -X OPTIONS \
  -H "Origin: https://aycweather.com" \
  -H "Access-Control-Request-Method: POST" \
  -H "Access-Control-Request-Headers: content-type" \
  https://grafana.ageddon.com/api/ds/query

Help Part One · the original request

The ask in one line: add CORS headers for https://aycweather.com on POST /api/ds/query at grafana.ageddon.com, and answer the OPTIONS preflight there too.

Why

The weather page reads the station through a small GitHub Actions updater that queries Grafana every minute and publishes a JSON file. When that updater falls behind, the page can't ask Grafana from the browser (no CORS headers, so the browser blocks the request) and has to fall back to iframes. With the headers below, the page could query the station directly and always draw its own charts.

It only needs the anonymous datasource query the updater already uses. No credentials or cookies are involved, and nothing else on the server needs to change.

Headers needed on /api/ds/query

Access-Control-Allow-Origin: https://aycweather.com
Access-Control-Allow-Methods: POST, OPTIONS
Access-Control-Allow-Headers: Content-Type
Access-Control-Max-Age: 86400

The browser sends an OPTIONS preflight first. Grafana returns 404 for that, so the proxy has to answer it itself with a 204 and the headers above, then add the Allow-Origin header to the proxied POST response.

If the proxy is nginx

location = /api/ds/query {
    if ($request_method = OPTIONS) {
        add_header Access-Control-Allow-Origin  "https://aycweather.com" always;
        add_header Access-Control-Allow-Methods "POST, OPTIONS" always;
        add_header Access-Control-Allow-Headers "Content-Type" always;
        add_header Access-Control-Max-Age       86400 always;
        return 204;
    }
    add_header Access-Control-Allow-Origin "https://aycweather.com" always;
    proxy_pass http://grafana;
}

If the proxy is Caddy

@dsquery path /api/ds/query
handle @dsquery {
    @preflight method OPTIONS
    handle @preflight {
        header Access-Control-Allow-Origin  "https://aycweather.com"
        header Access-Control-Allow-Methods "POST, OPTIONS"
        header Access-Control-Allow-Headers "Content-Type"
        header Access-Control-Max-Age       "86400"
        respond 204
    }
    header Access-Control-Allow-Origin "https://aycweather.com"
    reverse_proxy grafana:3000
}

If it's only behind Cloudflare

A Cloudflare Worker on the route grafana.ageddon.com/api/ds/query can do the same thing: answer OPTIONS with a 204 plus the headers above, and add the Allow-Origin header to the response it fetches from the origin.

How to check it worked

This should print an access-control-allow-origin line:

curl -s -D - -o /dev/null -X OPTIONS \
  -H "Origin: https://aycweather.com" \
  -H "Access-Control-Request-Method: POST" \
  -H "Access-Control-Request-Headers: content-type" \
  https://grafana.ageddon.com/api/ds/query
